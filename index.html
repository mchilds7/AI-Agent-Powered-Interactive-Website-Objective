Every subject gets its own teacher.

Chalkroom is school help built as a team of AI assistants. Each one knows one subject well, and a router sends your question to the right one. A chatbot also runs the whole site, by typing or by voice.

    Your question goes to whichever assistant fits it best.

    The idea

    Chat shortcut: open the idea page

    Objectives

    • Give every school subject an assistant built for that subject.
    • Help students learn the method, not just get the answer.
    • Keep each assistant focused so answers stay on topic and at the right level.

    Key features

    • A router that picks the right assistant for each question.
    • Seven specialists, each with its own teaching style.
    • Hand-offs when a question belongs to a different subject.
    • A study coach that helps plan the work.

    Potential impact

    • Students get quick, focused help at any hour.
    • Learners without a tutor get something close to one.
    • Teachers get students who arrive with better questions.

    What is your new idea?

    One website with a team of AI assistants for school, each dedicated to a single subject: math, science, writing, history, technology, languages, and study skills. Instead of asking one chatbot to handle everything, you ask a team. A router reads your question and hands it to the specialist who should answer it.

    What problem does it solve?

    A single general chatbot has to cover every subject, every grade level, and every teaching style at once. That tends to produce answers that are generic or pitched at the wrong level. Many AI tools also hand over finished answers, which makes it easy to skip the learning. Chalkroom gives each subject a focused assistant that explains the steps and guides the student.

    Who will benefit from it?

    Middle school, high school, and college students who need help outside class hours. Students who can't afford a tutor. Teachers and tutors, who can point students to a tool that coaches instead of copying answers.

    How will AI agents solve the problem?

    Each assistant is an agent with a narrow job: its own knowledge, its own rules, and its own way of teaching. The router agent decides who answers. If a question crosses subjects, the assistant that receives it says so and offers a hand-off. The coach agent keeps track of the plan: what to study, in what order, and when to take a break.

    What makes your idea different from existing solutions?

    Most AI help is one general assistant. Chalkroom is a team with a visible structure: you can see who is answering and why. Each assistant follows subject-specific rules, such as the writing assistant helping you improve an essay rather than writing it for you. The result is closer to a school's hallway of teachers than a single search box.

    What additional features would you like to develop in the future?

    • Connect each assistant to a full language model, with subject-specific instructions and sources.
    • Upload class notes and assignments so assistants can use your own material.
    • Quizzes and flashcards built from each conversation.
    • Progress tracking, so the coach can spot weak topics.
    • Voice input, multiple languages, and strong accessibility support.
    • A teacher dashboard to set rules for how much help each assistant gives.

    How do the agents run the website?

    The Control chat is a team of agents behind one interface. Every command goes through the same five steps: recognize what you said, identify the action, select the right website function, execute it, and confirm the result. Specialist agents handle navigation, theme changes, assignments, shopping, and media, and the subject assistants answer school questions. Open "Agent steps" under any Control reply to see the steps it took.

    Prototype note: the assistants on this site use built-in subject knowledge to show how the team works. They are not connected to a language model yet.

    How the AI agents work

    Behind the one chat are small agents, each with one job. Every command goes through the same five steps.

    1. Recognize. The right agent understands the request.
    2. Identify the action. It works out what to do, such as "change the background color to blue."
    3. Select the function. It picks the website function for that action.
    4. Execute. The function runs on the page.
    5. Confirm. The agent checks the page itself and reports whether it worked.

        Security and privacy

        This site is built so it needs very little from you, and keeps what it does need on your own device.

        Chat shortcut: open the security page, check my password, erase my data

        How the site protects you

        • Content security policy. The browser only runs scripts and loads files from this site. The only outside request is the fonts.
        • Clean input. Anything you type has its tags removed and its length capped, and is shown as plain text, never as code.
        • No payment details. The store is a demo. Card-number-like text typed into the chat is blocked and hidden, and no payment fields exist.
        • Confirmation before actions that matter. A demo order and a data erase both wait for a short, clear "confirm."
        • No tracking. No cookies, analytics, or accounts on a server.
        • Voice only when you ask. The microphone starts only when you press Speak.
        • Never type a password or card number into the chat. Use the password lab below, which runs only in your browser.

        How it is built

        • Files: index.html (all pages), styles.css (design), data.js (assignments, products, scenes, and charts data), app.js (pages and subject assistants), pages.js (dashboard, activities, security, contact), control.js (the chatbot and its agents), and four media files.
        • One site: every page is a section of index.html, shown by the menu or the chatbot. There are no separate sites.
        • Editing content: change assignments, products, backgrounds, and media file names in data.js. To use a different movie, set movie: 'your-file.mp4' in its media line.
        • Hosting: plain static files, so GitHub Pages works with no setup.
        • Browsers: current Chrome, Edge, Safari, and Firefox. Voice input works in Chrome, Edge, and Safari.

        Limits

        • The assistants and the chatbot understand phrases and keywords, not open-ended language. They are not connected to a large language model.
        • The store is a demo with a fixed catalog. No real orders happen.
        • Everything is saved only in your own browser.
